The types say what agents read the compiled code for. `BuiltInIndicators` lists the 134 built-in indicators by id, with each one's inputs (their defaults and ranges in their notes) and the keys of the lines it draws. `addIndicator('rsi', { period: 14 })` offers the ids and inputs as you type, and a misspelt input fails the type check (`{ stddev: 2 }` for the bands' `stdDev`): in TypeScript, an object literal with an input the built-in doesn't have no longer compiles; it was ignored. Values stay as loose as they were (text for a number, any text for a kind), but `true` or `false` for a number fails. Any id still takes any inputs, for indicators a plugin registers (`IndicatorId`, `IndicatorParamsFor<Id>`); a function generic over the id should type its inputs `IndicatorParamsFor<Id>`. The components' `indicators` prop takes the same ids. Notes on fields that the published types left out are in them: a replay's `interval` and `speed` (one bar every `interval / speed` ms), the stream's reconnecting (`StreamConfig.reconnect`) and the `DataAdapterConfig` fields it doesn't pass, a market's lot, price step, limits and session times, the trading adapter's events. `applyOverrides`, the `overrides` option and `CHART_STYLE_KEYS` say that `series.candlestick.upColor` / `downColor` colour the wicks too and that `wickUpColor` / `wickDownColor` part them. The widget's `features` and `depthLadder` say a switch never adds a part: `features: { depthLadder: true }` alone makes no ladder.
