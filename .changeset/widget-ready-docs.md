The widget's `onReady` runs once the widget is built, in a microtask after `new ChartWidget()` returns, and gets the widget as well as its chart: `onReady: () => widget.openPanel('watchlist')` works (it threw, the widget's name not yet set). For code written to the old order: the statements right after the constructor now run before it (a `setData` there comes first; a variable `onReady` sets isn't set yet, so use `widget.getChart()`), a view shared in the URL is still put back after it, and an error it throws is reported as uncaught rather than by the constructor. It no longer runs for a widget destroyed first. A shared link cut short (`#tcw=` that isn't a URI component) is left alone instead of making the constructor throw. The docs say what agents had to read the compiled code for: the `watchlist` option is a panel of the dock that starts shut (`widget.openPanel('watchlist')`), a widget without `adapter` connects nowhere and shows the bars you give `setData`, `isFeatureOn` answers for one switch as set (with `replay: false`, `isFeatureOn('toolbar.replay')` is still `true`), `saveState` / `setAutoSave` / `loadState` / `loadStateFromStorage` say what a layout holds and when it is written, and the React component says which props follow their changes, what a new `data` array does, and what unmounting does.
