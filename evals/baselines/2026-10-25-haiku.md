# 2026-10-25: Haiku, bare and skill

The first run with a smaller model, on the same code as
[Sonnet's run of the day](2026-10-25-sonnet.md): Sonnet passes nearly every
task either way, so its pass rates can't tell the arms apart.

- `main` at `beb6178`, the code released as 1.48.0 (the run's summary says
  1.47.0, as Sonnet's does); model `claude-haiku-5-5`, Claude Code headless.
- 24 tasks × 2 arms × 2 runs: 96 runs, $1.20 in all. No run failed in the
  setup, none changed its project's setup, none timed out.
- `pnpm eval --arms bare,skill --runs 2 --model haiku --concurrency 2`, no
  regrade needed.

## What it shows

- **Haiku does the tasks too**: 48 of 48 with the package alone, 47 of 48
  with the skill. The failure is a trap in the widget's options, not a
  weaker model (finding 10).
- **The skill saves more for Haiku than for Sonnet**: 13 turns against 18
  (−28%), 247k tokens against 447k (−45%), $0.010 against $0.015 a run.
  The largest savings are on indicators and alerts: 04 (28 turns → 12),
  24 (25 → 12), 03 (21 → 9), 23 (20 → 9), 07 (28 → 14).
- **Haiku takes more steps than Sonnet** (13 turns against 10 with the
  skill, 18 against 16 without) and more tokens (247k against 137k, 447k
  against 240k), at about a tenth of the cost a run.
- **It reads the compiled code more**: 10 runs of 48 with the skill
  (Sonnet: 2), 27 of 48 without (Sonnet: 22). With the skill it went there
  for what `interval` and `speed` mean in a replay (13), a toolbar button's
  spec (16), what the Terminal look sets (19, both runs), the Bollinger
  bands' inputs (23), the tick `updateLastBarFromTick` takes (02) and the
  watchlist's symbols (20). Findings 11, 12 and 14.
- **One run with the skill never opened it** (23, run 1) and passed by
  reading the compiled code.
- **Pass rates still don't separate the arms**; turns, tokens and the
  compiled code read do. Tasks that fail without the docs would.
