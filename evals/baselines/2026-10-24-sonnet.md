# Baseline, 2026-10-24: Sonnet, bare and skill

The first full run, before any of the [findings](../FINDINGS.md) were fixed:
what later runs are measured against.

- TradeCanvas 1.44.0, model `claude-sonnet-5-5`, Claude Code headless.
- 24 tasks × 2 arms (`bare`, `skill`) × 2 runs: 96 runs, $12.41 in all,
  about a minute a run. No run failed in the setup, none changed its
  project's setup, none timed out.
- `pnpm eval --arms bare,skill --runs 2 --model sonnet --concurrency 2`,
  then `pnpm eval:regrade`: the task 15 grader refused a right answer in
  three runs (replay and compare turned off as whole capabilities, not only
  their buttons) and was fixed after the run. As first graded: skill 94%,
  bare 96%.

## What it shows

- **Both arms do nearly every task.** Sonnet with the package alone passed
  48 of 48; with the skill, 46 of 48. At two runs a task the difference is
  noise; what failed is in the findings (6 and 7), and each would fail a
  person the same way.
- **The skill saves work.** With it, a task took 30% fewer turns (12 against
  16), 30% fewer tokens (177k against 251k) and 27% less money ($0.11
  against $0.15). It loaded in every run.
- **Where the skill took longer**, it left out the point of the task:
  alerts on a price fed by hand (07: 22 turns against 16; the skill shows
  `addAlert`, not what makes it fire) and a Vietnamese stock's time and
  numbers (10: 21 against 17; its recipe covers HOSE's steps and limits,
  not whether `setMarket(MARKET_HOSE)` sets the axis's zone, so the agents
  opened the preset to see what it holds). There the agents went to the
  compiled code in both arms.
- **Agents read the compiled code when the docs are silent**: 25 of 48 runs
  without the skill, 12 of 48 with it (a `.js` file of the packages read,
  searched or listed by name). What they were looking for is in finding 8.
- **The tasks are easy for Sonnet.** Pass rates can't separate the arms;
  turns and cost can. Harder tasks, or a smaller model, would show more.

## The two failures

- `18-widget-ladder.skill.1`: the answer opens the ladder from `onReady`,
  which uses the `widget` constant the constructor hasn't returned yet. It
  type-checks and throws when it runs. (Finding 6.)
- `20-widget-watchlist.skill.1`: the watchlist is made but never opened;
  the answer took "a watchlist sidebar on the right" at its word.
  (Finding 7.)

## What the runs were refused

Claude Code refused 2.4 shell commands a run without the skill and 1.3 with
it, each a turn lost: long chains of reads it wouldn't split (`cd … && ls;
grep … | head`), `grep` patterns with braces and quotes, and files written
through the shell (`cat > src/main.ts <<EOF`). 7 of them named a path
outside the project (`ls /c/Users`, `cat ~/…`, a wildcard that would match
the other arm's project too); all 7 were refused, and no command that ran
reached outside its project.
